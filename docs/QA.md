# Verificación de Filmma

Pruebas realizadas el 17 de octubre de 2026 en este Mac. Se separa la comprobación del editor y sus archivos de la inferencia real de modelos: una exportación MP4 de imágenes no acredita que se haya ejecutado MiniMax o LTX.

## Navegador y datos aislados

`scripts/qa-functional.mjs` abre Google Chrome en modo headless. Un proxy HTTP local envía todas las peticiones de API a un servidor con almacenamiento temporal, mientras sirve la interfaz compilada de Filmma. Los archivos multipart se transfieren como bytes originales. No se modifica el proyecto abierto de la persona; el informe registra hashes antes/después y cada petición enviada al servidor temporal.

Se verificaron **13 comportamientos** con resultado final satisfactorio. Las dos ejecuciones finales registraron el proyecto vivo intacto y cero errores JavaScript. Comprobado:

- Las seis secciones abren sin errores JavaScript.
- Título, premisa, acción y diálogo se guardan y sobreviven a recargar.
- La importación de una imagen desde el navegador conserva sus bytes exactos y la vincula al plano seleccionado.
- Un plano cambia de orden sin perder su identidad después de recargar.
- El botón de exportación produce un MP4 H.264/AAC de 1920×1080 y 4.021333 segundos para un montaje de cuatro segundos.
- La ausencia simulada de Codex produce un estado de error visible y recuperable. Esa prueba no llama a OpenAI.
- Crear otra película y reabrir la anterior conserva la historia.
- Una propuesta estructurada exige revisión antes de añadir planos. Una ejecución conjunta detectó que un aviso anterior podía retirar el botón Deshacer; se corrigió el temporizador y el recheck de revisar/añadir/deshacer pasó.
- Fotograma final, aspecto y fundido se conservan al recargar. El visor refleja la clase de aspecto elegida; los píxeles exportados se prueban por separado.
- El botón de generar pendientes añade un trabajo por plano. El ejecutable de inferencia está deliberadamente ausente en la prueba y no se carga ningún modelo.
- Los botones EDL y SRT esperan el guardado y descargan texto válido; el ZIP se exporta y se importa desde el navegador como película nueva, conservando las referencias.
- Una respuesta de sincronización retrasada con un clip nuevo no sobrescribe una elección manual hecha antes del guardado automático. Se retuvo la respuesta, se seleccionó otro clip en la biblioteca y se comprobó la elección en el visor, el servidor y después de recargar; el recurso generado siguió en la biblioteca.

La primera tentativa de importación falló por el transporte de interceptación de Playwright, que no conservaba el cuerpo de los archivos. Se sustituyó por un proxy de flujo HTTP y la importación pasó con igualdad de bytes. No fue un fallo de importación de la aplicación. Se conservan los informes anteriores como evidencia del diagnóstico.

Evidencias: `output/qa/qa-summary.json` reúne la última prueba de cada comportamiento a partir de `functional-complete.json` y `functional-final-sync.json`. Se conservan también los informes anteriores y `qa-montage.mp4`, `qa-montage.edl` y `qa-dialogues.srt`. El recheck final actualiza el selector de EDL/SRT tras convertirse en botones y comprueba las protecciones nuevas del cambio de proyecto. `scripts/qa-functional.mjs` admite `FILMMA_QA_CHECK` (expresión regular), `FILMMA_QA_REPORT` y `FILMMA_QA_URL` para repetir únicamente el comportamiento afectado.
